# Ошибки и решения

Формат: ошибка → причина → решение.

- `docker compose` не подключается к демону (`docker.sock: no such file`) → Docker Desktop не был запущен → запустили Docker Desktop.
- `docker-compose.yml` не запускался → внутри `services:` был вложен второй ключ `services:`, а `volumes:` тоже оказался внутри → переписали файл, `services` и `volumes` на верхнем уровне.
- В `requirements.txt` не было FastAPI, SQLAlchemy и т.д. → туда попал `pip freeze` из другого окружения (jupyter, pandas) → заменили на список прямых зависимостей проекта.
- Контейнер `api` не стартовал бы: команда запуска вызывает `alembic upgrade head`, а Alembic не был настроен → выполнили `alembic init` внутри контейнера и взяли URL базы из `DATABASE_URL` в `env.py`.
- Проверка изоляции показала, что второй пользователь видит чужую заметку → в shell-скрипте email генерировался через `$RANDOM` внутри `$(...)`, в zsh подоболочка дала одинаковое число, и «второй» пользователь оказался тем же самым (регистрация вернула 409, вход — в первого) → задали разные email явно; API работал верно (404). Вывод: в тестах проверять, что пользователи действительно разные (`/auth/me`).
- Ревью: пароль длиннее 72 байт (например, 72 русские буквы) давал 500 при регистрации и входе → bcrypt 5.0 бросает ValueError вместо обрезки пароля → в схеме проверяем длину в байтах (422), при входе такой пароль сразу неверный (401).
- Ревью: заголовок из одних пробелов принимался → проверялась только длина строки → сначала включили `str_strip_whitespace` для всей схемы, повторное ревью заметило, что так обрезается и текст заметки → обрезаем пробелы только в заголовке (`StringConstraints(strip_whitespace=True)`).
- Ревью: файл больше 20 МБ сервер сначала принимал целиком во временную папку и только потом отвечал 413 → проверка шла после чтения тела → middleware отклоняет запрос по заголовку `Content-Length` до чтения тела.
- Ревью: при обрыве загрузки или сбое БД на диске оставался файл без строки в БД → не было очистки при ошибке → `try/except` удаляет файл и откатывает транзакцию.
- Ревью: две одновременные регистрации с одним email давали 500 → проверка «есть ли email» и вставка не атомарны → ловим `IntegrityError` и отвечаем 409.
- Ревью: `%` в пароле БД ломал Alembic → configparser считает `%` спецсимволом → удваиваем `%` в `env.py`, в `.env.example` подсказка генерировать пароль из букв и цифр.
